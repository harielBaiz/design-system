# Color palette

A scale of raw colors to choose from. **Nothing here has a meaning yet.** A step is not “primary” or “error” until you give it a job.

Twelve hues and a neutral scale, each in steps from **50** (lightest) to **950** (darkest). Every step has the same perceived lightness in every hue, so 500 is a mid tone in red, in blue and in green alike. The palette is fixed: it does not change with the Theme switch.

When a color needs a job, add a semantic token in `tokens.css` that points to a palette step, for example `--text-info: var(--color-blue-700)`. Then components use the semantic token. Changing a color later is one edit.

## Reading the scale

- **50 to 200** are tints. Use them for backgrounds and fills behind dark text.
- **300 and 400** are light mid tones. Use them for borders, dividers and decoration, not for text.
- **500 and 600** are the strong mid tones. They suit fills, charts and icons. Check the contrast before putting text on them.
- **700 to 950** are shades. Use them for text on light backgrounds, or for surfaces in dark themes.

## Usage

### Best practices

- Pick **two or three hues** for a product and use the neutral scale for everything else.
- Keep the same step for the same job across hues, for example 100 for tinted surfaces and 700 for text on them. Steps line up, so the contrast stays predictable.
- Check contrast for **every** text and background pair, in every theme. A step that works on white may fail on a dark surface.
- Do not use color alone to carry meaning. Add an icon, a label or a pattern.

### Don't

- Don't use a palette color directly in a component. Use a semantic token.
- Don't mix steps from different hues to make a new in-between color.
- Don't use a tint (50 to 200) as text on white.

## Tokens

All steps are CSS variables named `--color-{hue}-{step}`, for example `--color-teal-600`. They are generated from one script, so every hue stays consistent:

```bash
node scripts/generate-palette.mjs
```

This writes `src/tokens/palette.css` (the variables) and `src/tokens/palette.ts` (the same values for docs and tools). To add a hue or change a step, edit the script and run it again. Do not edit the generated files by hand.

The success and danger scales (`--success-*`, `--danger-*`) are built from the green and red palette scales, so status colour and palette colour never drift apart. The warning and info scales and the neutral scale (`--n-*`) keep their own values.
