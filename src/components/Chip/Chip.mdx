# Chip

A token for a value people selected, a filter they can toggle, or an item they can remove.

<Primary />
<Controls of={ChipStories.Default} />

## Usage

### When to use

- Show the values a person has **picked**, such as selected skills or recipients.
- Offer **filters** they can switch on and off.
- Offer **suggestions** they can tap, such as suggested prompts.

### When not to use

- For a status or a count. Use `Badge`.
- For a long sentence. A chip holds one to three words.
- For navigation. Use a link or a tab.

### Chip or badge?

A chip is something a person **handles**: they pick it, toggle it or remove it. A badge is something a person **reads**. If it never reacts to a click, it is a badge.

### Best practices

- Keep chips short. Long text truncates (see Truncated).
- Chips are **not interactive** by default. Turn on `interactive` only when a click does something.
- Show a close button (`onClose`) only for values people can remove.
- Group related chips in a `ChipGroup` and give the group a name.

With `interactive`, the chip is a button. It has hover, focus and pressed states and takes `onClick`. Add `selected` to make it a toggle, which sets `aria-pressed`.

## Accessibility

- An interactive chip is a real `button`. It is reachable with Tab and activates with Enter and Space.
- A toggle chip sets `aria-pressed`. A selected state is also shown by fill, not only by colour.
- The close button is a separate button named “Remove” plus the chip text, for example “Remove Tokens”.
- A disabled chip sets `aria-disabled` and removes its buttons from the tab order.
- A static chip is plain text. Do not add click handlers to it. Use `interactive`.
